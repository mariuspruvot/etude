# Étude v1.2 — Design Spec: Localized agents + closing the open-loop gaps

- **Date**: 2026-05-27
- **Status**: Approved (2026-05-27)
- **Builds on**: `2026-05-27-etude-v1.1-design.md` (v1.1, merged via PR #3). v1.1 must be merged first.
- **Scope lock**: v1.2 ships **items 1–3 only** (agent localization, the `assess` language
  footer, and resolving the two §14 open questions). The v1.3 curated-overlay design is
  written as a **separate** doc (`2026-05-27-etude-v1.3-overlays-design.md`) and is
  **not implemented** in this cycle.

## 1. Summary

v1.1 made the spine open, self-extending, and multilingual — but two seams were left
unfinished and tracked for v1.2:

1. **The two sub-agents were never localized.** `grader` and `interviewer` carry no language
   rule, so their prose (verdict strengths/improvements, interview questions, follow-ups,
   debrief) is emitted in English regardless of the learner's `profile.md` `language`. The
   `interviewer` is the sharpest gap: it talks **directly** to the learner, unmediated by a
   skill that could re-localize. (Traced gap: v1.1 spec §11 listed the agents as "edited" but
   only the description was touched; surfaced again in PR #3 review.)
2. **The `assess` skill is the only learner-facing skill missing the `**Language:**` footer.**
3. **Two v1.1 §14 open questions stayed open:** the auto-promotion threshold (when the tutor
   *offers* to promote a niche to a personal module) and whether deep-dive explorations get
   `last_visited` tracking for spaced revision.

v1.2 closes all three. No new schema, no new state files, no change to the lint or the
integrity hook.

## 2. Goals & Non-Goals

### Goals
- Localize **all** learner-facing prose, including what the two sub-agents emit.
- Make `assess` consistent with the other learner-facing skills (language footer).
- Decide and implement the auto-promotion threshold and deep-dive spaced revision.

### Non-Goals
- NOT implementing curated overlays / layer 3 (that is v1.3 — design only, separate doc).
- NOT touching the repo `curriculum.md` schema, the lint, or the integrity hook.
- NOT enriching TypeScript/SQL from stub to flagship (out of scope until real-usage signal).
- NOT introducing a new state file or schema for revision (reuse the dated `explorations.md`).

## 3. Key Decisions

| # | Decision | Choice |
|---|----------|--------|
| 1 | How agents get the language | **Each agent reads `progress/profile.md` itself** (it has the `Read` tool). Self-contained; works even if invoked directly, no coupling to the calling skill. |
| 2 | What agents localize | **Prose only.** `grader`: `strengths`/`improvements`. `interviewer`: warm-up, verbal questions, follow-ups, debrief. Structured fields (`score`, `passed_tests`, `concept_levels` keys = concept tags), code, identifiers, CLI stay English. |
| 3 | Auto-promotion threshold | **Offer (never impose) on the 2nd visit of the same niche** in `explorations.md` (judgment-matched), **and always on explicit request.** |
| 4 | Deep-dive spaced revision | **`revise` also scans `explorations.md`**; the entry date is the `last_visited` proxy, **flat ~30-day interval**. Plus: a concept at `learning` with `last_graded: —` is treated as **due**. No new schema. |

## 4. Feature: Localized sub-agents

### 4.1 `grader`
- Add a first step: read `progress/profile.md`, take the `language` field (default `en` if
  absent).
- The structured verdict is unchanged in **shape**; only the prose fields are localized:
  - localized: `strengths`, `improvements`.
  - English/numeric (unchanged): `score`, `passed_tests`, `concept_levels` (keys are concept
    tags), and any code/identifiers/CLI/filenames quoted in the prose.
- The `grader` still returns a verdict **only** and does **not** modify files (integrity hook
  invariant unchanged). The `grade` skill — which already carries the language footer —
  transcribes the (already-localized) verdict into `feedback.md`, so prose stays consistent
  end to end.

### 4.2 `interviewer`
- Add a first step: read `progress/profile.md`, take the `language` field (default `en`).
- Localized prose: warm-up, the 2–3 verbal questions, follow-ups, time-pressure cues, and the
  final debrief (verbal score, coding score, communication notes, next steps).
- English (unchanged): code, identifiers, CLI, concept tags, the `solution_file` filename it
  tells the candidate to create, and the hand-off to the `grader` agent.
- The `interviewer` still does **not** write the candidate's code (hook + existing rule).

### 4.3 Shared footer
Both agents get the canonical footer line used across the skills (verbatim):

```
**Language:** write prose in the learner's `progress/profile.md` `language`; keep code, identifiers, CLI, and concept tags in English.
```

## 5. Feature: `assess` language footer

- Add the same `**Language:**` footer to `.claude/skills/assess/SKILL.md`.
- Nuance: `assess` runs **before** `language` is set on a first run. The footer is phrased so
  it applies **once the language is known/detected** — `assess` itself detects/sets the
  language (existing step), then localizes subsequent prose in the same session. The footer
  does not force prose before detection.

## 6. Feature: Auto-promotion threshold

- Rule added to `teach` and `deep-dive` (the two modes that log explorations): **OFFER**
  (never impose) to promote a niche to a personal module in `progress/<track>/extensions.md`
  when **either**:
  - the same niche appears for the **2nd time** in `progress/<track>/explorations.md`
    (topic matching is by judgment — the log is free-text, dated entries), **or**
  - the learner explicitly asks ("make this a real module").
- The promotion action itself is unchanged from v1.1 (append an `xNN` module with a
  `personal:`-prefixed concept, mastery, exercise_seeds; mention it can later be PR'd into the
  repo). v1.2 only pins **when the offer fires**.

## 7. Feature: Deep-dive spaced revision

- `revise` reads **both** `progress/skills.md` (as today) **and**
  `progress/<track>/explorations.md`.
- For explorations: the most recent dated entry for a topic is its `last_visited`. A topic not
  revisited in **> 30 days** (flat interval — explorations are ungraded, so there is no level
  to derive a per-level interval from) surfaces as an **optional light recall**: a short
  conceptual question, or an offer to re-`deep-dive`. Acting on it writes a new dated entry to
  `explorations.md`, which naturally resets `last_visited`.
- **New due rule**: a concept at level `learning` with `last_graded: —` (i.e. nudged by a
  deep-dive but never graded) is treated as **due** — testing it is exactly the point. This
  closes the gap where v1.1's interval math (days since `last_graded`) could not compute a due
  date for ungraded-but-nudged concepts.
- `revise` stays read-mostly: it generates a recall exercise via the `exercise` flow and
  grades via the `grade` flow (both already update state); it does not invent new state.

## 8. Data-model changes

- **None to schemas.** No new files, no new frontmatter fields.
- `progress/README.md` documentation only: a one-line note that `revise` treats the latest
  dated `explorations.md` entry for a topic as its `last_visited` (flat ~30-day interval), and
  that a `learning` concept with `last_graded: —` is due. (Documentation, not schema.)

## 9. Components touched

- **Edited agents**: `.claude/agents/grader.md`, `.claude/agents/interviewer.md`
  (read `profile.md` for `language`; localize prose; add footer).
- **Edited skills**: `assess` (footer), `teach` (2nd-visit promotion offer),
  `deep-dive` (2nd-visit promotion offer), `revise` (scan `explorations.md` + due rule).
- **Docs**: `progress/README.md` (revision-of-explorations note).
- **Tests**: a new check/test asserting the language rule is present in **both** agents
  (required by the workflow: editing a localized agent must add a test/verification that the
  language instruction is there).
- **Unchanged**: repo `curriculum.md` + lint; integrity hook + its tests; all other skills'
  bodies (they already carry the footer from v1.1).

## 10. Verification

- Hook + lint unchanged → existing test suites still pass (no regression).
- New agent-language check passes (the rule is present in `grader.md` and `interviewer.md`).
- All `.claude/skills/*/SKILL.md`, `.claude/agents/*.md`, `.claude/commands/*.md` still parse
  (frontmatter `---`).
- Manual walkthrough additions:
  - (a) `/language fr` then a graded exercise → `feedback.md` strengths/improvements in
    French, `concept_levels`/score/code English.
  - (b) `/interview` in French → questions + debrief in French, `solution_file` name + code
    English.
  - (c) deep-dive the same niche twice → on the 2nd, the tutor offers promotion to
    `extensions.md`.
  - (d) `/revise` after a deep-dive on an ungraded niche > 30 days old → it surfaces as a
    light recall; a `learning` concept with `last_graded: —` is offered for revision.

## 11. Assumptions

- *Agents reading `profile.md` for `language` is reliable and cheap* — they already have the
  `Read` tool and a known path; default `en` if the file/field is absent. Confirm in the
  French walkthrough (a, b).
- *Localizing only prose in the grader verdict keeps `feedback.md` consistent* — because the
  `grade` skill (already localized) transcribes the already-localized verdict. Confirm in (a).
- *Topic matching in `explorations.md` is by judgment* — the log is free-text dated entries;
  there is no exact-match key, so "2nd visit of the same niche" is a tutor judgment, not a
  string equality. Accepted as intentionally fuzzy for a personal repo.
- *A flat 30-day interval for explorations is a reasonable default* — chosen because
  explorations are ungraded (no level → no per-level interval); revisit if it feels too
  frequent/rare in practice. `[claude-guessed: 30 days]`
- *Treating `learning` + `last_graded: —` as due will not spam revision* — there are few such
  concepts (only deep-dive nudges produce them) and acting on them sets a real `last_graded`.
