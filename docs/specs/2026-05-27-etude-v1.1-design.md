# Étude v1.1 — Design Spec: Open & Adaptive Curriculum (+ multilingual)

- **Date**: 2026-05-27
- **Status**: Approved (2026-05-27)
- **Builds on**: `2026-05-27-etude-design.md` (v1). v1 must be merged first.
- **Scope lock**: v1.1 **proves the on-demand framework flow only** — no curated framework
  overlays ship in v1.1; curated overlays/sub-tracks arrive later via the promotion path.

## 1. Summary

v1 shipped a **closed, curated spine**: each track's `curriculum.md` declares a fixed set
of modules and a closed concept vocabulary, and the lint enforces that closure. That gives
structure and reliable competency tracking — but in use it reads as a **cage**: nothing
tells the tutor it may leave the path, niche topics have no home, and capstone projects
feel fixed.

v1.1 keeps the spine as a **scaffold and coverage guarantee**, but makes it **open and
self-extending**, and adds a **teaching-language preference**. The guiding principle:

> **The curated curriculum is a spine, not a ceiling. Completeness comes from generation +
> adaptivity + self-extension — never from hand-enumerating every niche.**

## 2. Goals & Non-Goals

### Goals
- Let the learner (and the tutor proactively) go **beyond the curated modules** — niche
  topics, arbitrary depth — without losing structure or tracking.
- Let each learner's map **grow** with them, persistently, without editing the shared repo.
- Add a **deep-dive** discussion mode for thorough learning.
- Teach in the learner's **preferred natural language**, changeable anytime.
- Increase **exercise variety** via formats, not a hand-written bank.

### Non-Goals
- NOT removing or bypassing the curated spine (rejected "agent-driven, spine optional"
  option — it sacrifices the structured progress + transfer that make Étude valuable).
- NOT hand-authoring exhaustive curricula or exercise banks (exercises stay generated).
- NOT changing the v1 integrity model (the hook still guards `progress/*/exercises/*`).

## 3. Key Decisions

| # | Decision | Choice |
|---|----------|--------|
| 1 | Ambition | **Self-extending spine** — keep the curated spine, make it open + growable (not spine-optional). |
| 2 | Where growth lives | **Per-learner, in `progress/` (gitignored)** — never mutating the shared repo curriculum. |
| 3 | Off-curriculum topics | **All modes accept arbitrary topics**; tutor may propose branches off the path. |
| 4 | Tracking model | **Two-tier**: curated concepts → formal levels + transverse transfer; personal/ad-hoc → tracked separately, track-local by default. |
| 5 | deep-dive | **New mode/skill** (open Socratic discussion), distinct from the one-screen `teach`. |
| 6 | Language | **`language` in `profile.md`**; prose localized, code/identifiers/CLI stay English; changeable. |
| 7 | Exercise variety | **Vary formats** (implement/debug/refactor/explain/extend/write-tests) + multiple seeds; no exercise bank. |
| 8 | Growth → sharing | A good personal extension can be **PR'd into the repo curriculum** (personal → shared). |
| 9 | Coverage strategy | **3 layers**: curated language *core* + on-demand generated frameworks/libs/niches (Context7) + promotion of popular ones. We never pre-enumerate everything. |
| 10 | Frameworks | **On-demand by default** (generated under the language track, remembered as personal extensions); curated sub-tracks/overlays only via promotion for the popular few. |
| 11 | TypeScript | **First-class `typescript` track** (fits the typed-stack philosophy); the JS stub becomes TS-first (JS = subset). React/Vue/etc. are on-demand extensions of it. |

## 4. Feature: Teaching language

- `progress/profile.md` gains a `language: <bcp47>` field (e.g. `fr`, `en`, `es`).
- `assess` sets it on first run (detect the language the learner writes in, or ask).
- The router + every learner-facing skill (`teach`, `exercise`, `hint`, `grade` feedback,
  `interview`, `deep-dive`, `mini-app`) gets one rule: *"Write all prose — explanations,
  exercise statements, feedback — in the learner's `language`. Keep code, identifiers, CLI
  commands, file contents, and canonical technical terms in their original form (usually
  English). Concept tags stay English (internal tracking keys)."*
- Changeable: natural language ("parle-moi en anglais") updates `profile.md`; optional
  `/language <code>` command. `[claude-guessed: command name]`

## 5. Feature: Off-curriculum openness

- **Every mode accepts an arbitrary topic string** (one topic per invocation — keeps focus;
  invocations are unlimited and a topic may be broad, e.g. "the whole asyncio ecosystem"),
  not only declared concepts/modules.
  `/next "goroutine scheduler internals"`, `deep-dive "Go's escape analysis"`,
  `mini-app "a TUI file browser"` all work even with no matching module.
- **Tutor-proposed branches**: after a module, the tutor may offer to go deeper or sideways
  ("you've got interfaces — want type sets & `constraints`? off the standard path but
  builds on this").
- The curated path remains the **default suggestion** and the **coverage guarantee**; the
  learner is never blocked from leaving it.

## 6. Feature: Self-extending spine (the core mechanism)

Growth lives in the learner's gitignored `progress/`, never in the shared repo:

- **`progress/<track>/extensions.md`** — per-learner modules the tutor *promotes* when the
  learner repeatedly explores a niche. Same shape as a curriculum module (id prefixed
  `x01`, concepts, mastery, seeds), but **not linted** (it's user data). The tutor reads
  **both** the repo `curriculum.md` (shared spine) **and** this file.
- **`progress/<track>/explorations.md`** — a lightweight log of ad-hoc digressions
  (topic, date, what was covered), so exploration is remembered without inflating the
  closed concept vocabulary.
- **`skills.md`** — curated concepts tracked as today (formal levels + transverse). Personal
  concepts (from `extensions.md`) are tracked too but tagged `personal:` and are
  **track-local by default** (no cross-track transfer claims — avoids garbage transfer).
- **Promotion path**: a personal extension that proves valuable can be PR'd into the repo's
  `tracks/<track>/curriculum.md` → then it becomes shared, linted, and transverse. Personal
  → community.

This preserves v1's lint, closed vocabulary, and transfer model intact (all unchanged in
the repo), while the per-learner layer is free and unbounded.

## 7. Feature: `deep-dive` mode

- New skill `.claude/skills/deep-dive/SKILL.md` + `/deep-dive [topic]` command.
- Open, Socratic, back-and-forth discussion that goes deep on a concept (internals,
  trade-offs, cross-language contrasts, history, edge cases). Context7-backed.
- May write **example code in chat** (exposition) — but NOT into `progress/*/exercises/*`
  (hook-guarded), and it never solves a pending exercise.
- Updates `explorations.md` with what was covered; may nudge a concept to `learning`; offers
  an exercise or a promotion-to-extension at the end when warranted.
- Complements `teach` (the crisp one-screen lesson) — deep-dive is "office hours".

## 8. Feature: Exercise variety (no bank)

- The `exercise` skill varies the **format**, not just the topic:
  `implement` · `debug` (given broken code, fix it) · `refactor` · `read-and-explain` ·
  `extend` (add a feature to working code) · `write-tests`.
- It tracks recent formats/topics (via `log.md`) to **avoid repetition** and rotate angles.
- Flagship curricula get **more `exercise_seeds` per module**, phrased as angles, to widen
  generation — still seeds, never full exercises.
- For `debug`/`extend`/`refactor` formats: the starter (broken/partial code) goes in
  `prompt.md`; the learner still writes the fix in their own `solution_file` (hook holds).

## 9. Curriculum richness (principle, not a bank)

- Enrich the Go/Python flagships with a few more modules + more varied seeds so the
  out-of-the-box depth is good. But **do not chase exhaustiveness by hand** — the long tail
  is served by off-curriculum openness + self-extension + Context7. State this as a
  contributor principle in the repo.

## 9b. Coverage strategy — "how do we cover everything?"

The honest answer: **we never pre-write everything.** Languages × frameworks × libraries ×
versions is unbounded and would be perpetually stale (Django/React/FastAPI move fast).
Coverage is delivered in **three layers**:

1. **Curated language core (the spine).** Finite and stable per language: syntax, types,
   errors, concurrency, testing, baseline tooling. Worth curating well — it rarely changes.
   This is what `tracks/<lang>/curriculum.md` holds. Tool lists in modules are
   **representative, not exhaustive** (e.g. Python: mypy lives in m03, pytest in m07; an
   unlisted tool is still taught on demand).
2. **On-demand generation (the long tail).** Frameworks (Django, FastAPI, React, Vue),
   libraries (SQLAlchemy, Pydantic), niche tools, advanced topics. When the learner asks
   ("teach me FastAPI"), the tutor builds the path **live from current docs via Context7**
   and remembers it as a **personal extension** (`progress/<track>/extensions.md`). Zero
   hand-curation, never stale.
3. **Promotion (popular → shared).** A frequently-used framework/path can be PR'd into a
   curated **sub-track or overlay** — e.g. `tracks/python/frameworks/fastapi.md` or a
   dedicated `tracks/fastapi/` track — so it ships shared + linted. Opt-in, community-driven.

**Frameworks are layer 2 by default**, not layer 1 — they are the prime use case for
generation + Context7, precisely because curating them by hand is a losing, always-stale
battle. Only the few highest-demand frameworks graduate to layer 3.

### TypeScript

`typescript` becomes a **first-class track** (fits Étude's typed-stack philosophy — TS is to
JS what mypy-typed is to untyped Python). The v1 JavaScript stub is reworked **TS-first**
(plain JS treated as a subset). Front-end frameworks (React, Vue, Svelte) and runtimes
(Node, Bun) are **on-demand extensions** of the TS track, promotable to overlays later.

### What this means for the flagships

- Keep enriching the **core** of Go / Python / TypeScript (more modules + more varied
  seeds) — bounded, high-value work.
- Do **not** attempt to ship curated framework curricula in v1.1; prove the on-demand
  framework flow instead (walkthrough: "learn FastAPI" with no FastAPI module → generated
  path + personal extension).

## 10. Data-model changes (additive, backward-compatible)

- `profile.md`: + `language`.
- New per-track files: `extensions.md`, `explorations.md` (both gitignored under
  `progress/`; documented in `progress/README.md`).
- `skills.md`: personal concepts allowed, tagged `personal:` (track-local).
- No change to repo `curriculum.md` schema or the lint (the closed model stays for the
  shared spine).

## 11. Components touched

- **New**: `deep-dive` skill + `/deep-dive` command; optional `/language` command.
- **Edited skills** (add language rule + arbitrary-topic acceptance + extensions/explorations
  awareness): `assess`, `teach`, `exercise`, `grade`, `hint`, `status`, `mini-app`,
  `interview`, `revise`, `validate`, root `CLAUDE.md`.
- **Edited agents**: `grader` (grade arbitrary-topic + extension exercises),
  `interviewer` (language).
- **Tracks**: rework the JS stub into a **TS-first `typescript` track**; enrich Go/Python/TS
  *cores* with more modules + varied seeds (no framework curricula — those stay on-demand).
- **Docs**: `progress/README.md` (new files + language), README (language + openness +
  coverage strategy), flagship curricula (more seeds/modules).
- **Lint**: unchanged for the repo; optionally a separate, non-blocking validator for
  `extensions.md` shape could be added later (out of scope here).

## 13. Assumptions

- *Per-learner `extensions.md`/`explorations.md` read alongside the repo curriculum is
  enough for the tutor to treat personal modules as first-class* — needs a walkthrough to
  confirm the tutor reliably reads both. `[claude-guessed]`
- *Keeping personal concepts track-local avoids polluting transverse transfer* — chosen to
  protect the transfer model; revisit if cross-track personal transfer is later wanted.
- *Localizing prose while keeping code/terms English is the right cut* — standard for
  technical pedagogy; confirm with a non-English walkthrough.
- *Exercise-format variety is driven by skill instructions + `log.md` history, no new
  state needed* — assumes the tutor honors the "avoid recent formats" rule.
- *Command names `/deep-dive`, `/language`* — proposed. `[claude-guessed]`

## 14. Open questions
