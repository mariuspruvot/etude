# Étude v1.1 Implementation Plan — Open & Adaptive Curriculum (+ multilingual)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make Étude's curated spine *open and self-extending*, add a deep-dive discussion mode, teach in the learner's language, vary exercise formats, and add a first-class TypeScript track — without breaking v1's lint, integrity hook, or transfer model.

**Architecture:** All v1 invariants hold (the repo `curriculum.md` stays closed + linted; the hook still guards `progress/*/exercises/*`). New capability lives in **per-learner files under the gitignored `progress/`** (`extensions.md`, `explorations.md`) and in **instruction edits** to the existing Markdown skills/router. No change to the two Python artifacts' behavior. Spec: `docs/specs/2026-05-27-etude-v1.1-design.md`.

**Tech Stack:** Markdown + YAML frontmatter; existing `python3` hook + `uv`/`pytest`/`ruff`/`mypy` tooling (unchanged); `pyyaml` for the lint (unchanged); Context7 for on-demand framework/library freshness.

**Invariants (do NOT violate):**
- Never edit the repo `tracks/<t>/curriculum.md` schema or relax the lint — the shared spine stays closed/linted.
- Per-learner growth (`extensions.md`, `explorations.md`) is gitignored and **not** linted.
- No skill may instruct Claude to write under `progress/*/exercises/*` except `prompt.md`/`feedback.md` (hook-enforced).
- Code/identifiers/CLI/concept-tags stay English; only prose is localized.

**Canonical strings (use verbatim where referenced):**
- LANGUAGE_RULE: `Write all prose (explanations, exercise statements, feedback) in the learner's profile language; keep code, identifiers, CLI commands, file contents, and concept tags in English.`
- OPENNESS_RULE: `The learner may request any topic, even one with no module. Generate a path for it using Context7 for current docs; you are not limited to the curated modules. Proactively offer to go deeper or branch when it serves the learner.`
- EXTENSIONS_RULE: `Read BOTH tracks/<track>/curriculum.md (shared spine) AND, if present, progress/<track>/extensions.md (the learner's promoted personal modules). Treat personal modules as first-class.`

---
```markdown
name: deep-dive
description: Use when the learner wants to explore a concept or topic in depth — internals, trade-offs, cross-language contrasts, history, edge cases — in an open Socratic discussion rather than the short teach lesson.
---

# Deep-dive

Determine the active track from what the learner just said, else from `progress/profile.md`
(`active_track`). The topic may be ANY topic, with or without a curated module.

1. Open, back-and-forth discussion that goes as deep as the learner wants: internals,
   trade-offs, "why is it designed this way", cross-language contrasts, edge cases. Pull
   current docs via Context7 — do not rely on recollection for libraries/APIs.
2. You MAY write example code in the chat for exposition. You must NOT write into
   `progress/*/exercises/*` (the hook blocks it), and you must not solve a pending exercise.
3. Log what was covered in `progress/<track>/explorations.md` (topic, date, key points).
   You may nudge a related concept to `learning` in `skills.md` if genuinely demonstrated.
4. Promotion: if this niche has been explored repeatedly, OFFER to promote it to a personal
   module in `progress/<track>/extensions.md` (id `xNN`, `personal:` concept).
5. End by offering a relevant exercise (hand to `exercise`) when it would help.

**Language:** write prose in the learner's `progress/profile.md` `language`; keep code, identifiers, CLI, and concept tags in English.
```
